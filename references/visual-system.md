# 视觉系统

在为新项目确定字体、文字层级和配色时读取本文件。只固定需要建立的语义关系，不固定视觉结果；具体字体、色相、色值、面积和表面关系必须根据当前产品推导。

## 先理解产品

在选择字体或颜色前回答：

- 产品属于工具、内容、交易、娱乐、教育、品牌展示还是其他类型。
- 用户是谁，使用频率、设备、光线环境和阅读时长如何。
- 品牌需要表达专业、可靠、亲切、精密、活力、温暖或其他什么性格。
- 页面以文字、数据、图像、操作还是沉浸体验为主。
- 项目是否已有品牌色、字体、设计变量或必须兼容的资产。

没有这些判断时，不要直接选择流行字体或主题色。

## 字体系统

- 根据语言覆盖、字符质量、阅读长度、数据密度和品牌气质选择字体，不固定使用某个字体家族。
- 优先使用项目已有字体；需要新字体时，确认授权、加载性能、中文字符覆盖和回退字体表现。
- 为以下语义角色建立变量，而不是在组件中散落字号与字重：

| 角色 | 用途 | 默认关系 |
| --- | --- | --- |
| 页面标题 | 说明当前视图 | 克制突出，不形成巨型标题 |
| 区段标题 | 划分主要内容组 | 明显低于页面标题 |
| 组件标题 | 面板、弹窗和紧凑区域 | 接近正文，仅提高字重或少量字号 |
| 正文 | 主要阅读和说明 | 作为整套比例的基准 |
| 辅助文字 | 描述、时间和次要信息 | 可略小或降低颜色层级，但仍清晰可读 |
| 标签与说明 | 表单、表头和元数据 | 紧凑稳定，不低于可读下限 |
| 数据 | 数字、金额、计数和时间 | 根据扫描需要使用等宽数字 |
| 控件文字 | 按钮、菜单和选项 | 与控件高度、图标和操作重要性匹配 |

- 先确定正文字号，再按内容层级推导其他字号；保持层级差异清楚但不过度跳跃。
- 任何语义角色和响应式状态的最终计算字号都不得超过 `22px`；如果层级不够，优先调整字重、颜色、留白和位置，不增加字号。
- 中文界面主要依靠字号、字重和颜色建立层级，不使用过密或负字距制造紧凑感。
- 同一语义角色在不同页面保持一致；响应式只在确有空间压力时调整，不按视口宽度连续缩放字体。

## 配色工作流

### 1. 提取约束与依据

- 先收集已有品牌色、Logo、产品图片、行业材料、内容主题、使用环境和竞品禁区；不能只凭产品名称联想颜色。
- 将依据归纳为中性色温度、界面明暗、期望情绪、允许的色彩强度和必须避开的语义冲突。
- 品牌资产存在时，区分“必须原样使用的品牌色”和“可以从品牌色推导的界面色”，不要让 Logo 颜色直接覆盖所有表面。
- 从图片或实物提取颜色时，把原始颜色视为线索，重新调整明度与色度后再用于界面；不直接复制受光线影响的取样值。

### 2. 先验证明度骨架

- 暂时以灰度观察画布、表面、主要文字、辅助文字、禁用文字和阴影，确认选定颜色失去色相后仍有清晰层级；这是一项验证，不要求最终界面从中性色开始。
- 中性部分可以带有与品牌一致的轻微冷暖倾向；彩色表面则按选定模式控制明度、色度与前景对比。
- 画布、表面和次级表面必须有清楚的层级关系；可以使用颜色，但不能把多个无语义浅色块拼成信息结构。
- 主要文字保持接近中性，避免用主题色染黑正文；辅助文字通过明度降级，不通过变脏或变灰到不可读来降级。

### 3. 生成候选方向

- 没有成熟品牌色时，根据同一产品语境内部生成 `2–3` 个候选方向，再选择其中一个；候选必须在色相关系、色温或表现强度上有真实差异。
- 每个候选至少放入主要按钮、链接、选中项、弱主题背景、焦点环、正文、辅助文字和一组语义状态中预览，不只展示几块色板。
- 参考案例中的颜色只能作为候选来源。多个无关产品共享同一套蓝灰、紫色、米色或其他流行模板时，视为低辨识度结果并重新推导。
- 选择能够同时满足品牌含义、内容关系、可读性和整页协调的方向；不能因为单个主题色漂亮就选择整套方案。

### 4. 建立语义令牌

- 选定方向后再落实为项目自己的色值与语义变量；NiceUI 本身不保存固定色板。
- 使用感知更均匀的颜色空间检查明度与色度变化，例如 OKLCH；状态阶梯优先保持色相稳定，再调整明度和色度。
- 为每个实际会组合出现的前景与背景建立成对令牌，例如主题色与其上文字、错误弱背景与错误文字，不能只定义孤立颜色。
- 深色模式重新确定表面明度、颜色色度和前景关系，不从浅色模式机械反转。

## 色彩模式

先选择一种主要模式，再生成具体颜色。不要把所有模式混在同一页面。

### 中性主导

- 使用白、近白、灰、近黑或轻微冷暖倾向承担大部分面积。
- 用一个品牌色强调主要操作、链接、选中和少量数据。
- 适合后台工具、表格、表单、个人资料和需要长期使用的工作界面。

### 单色沉浸

- 使用一个高识别色或连续渐变形成完整首屏场景，导航、文字、按钮和产品演示建立明确前景。
- 强色必须连续而有边界，不能继续拆成许多互相竞争的彩色区块。
- 适合消费产品、媒体、创意工具或品牌首屏；进入高频工作区后通常降低色彩强度。

### 深色聚光

- 使用近黑表面承载内容，以一个冷色、暖色或发光边缘聚焦产品、数据或核心动作。
- 控制彩色光晕范围，确保暗部仍能区分导航、表面、边界和禁用状态。
- 适合安全、金融、AI、开发者工具和需要精密感的展示场景，但不能自动套用“科技蓝紫”。

### 内容取色

- 从产品截图、人物、商品、作品或环境图片中提取一个主色与必要辅助色。
- 让图片承担主要色彩，界面表面保持中性或低色度，使内容成为视觉中心。
- 适合作品集、商品、旅行、社交和内容产品。

### 低色度分类

- 使用数个明度接近、色度克制的浅色表面区分并列指标或类别。
- 每种颜色必须对应稳定类别，并在灰度下仍通过文字、图标和位置保持可区分。
- 仅用于少量同级模块；如果彩色卡片成为整页结构，应改回中性表面或减少类别数量。

## 色彩关系

- 根据选定色彩模式决定画布面积；中性主导、单色沉浸、深色聚光和内容取色都必须让文字、导航、产品内容与操作形成稳定前景，不预设近中性画布。
- 不把主题色稀释后机械铺满背景、卡片、导航和文本。大面积颜色需要是一个有边界的连续场景，而不是遍布所有组件的颜色滤镜。
- 同一页面通常只保留一个主要品牌色。第二强调色必须承担明确且不同的功能，并在色相、明度和面积上与主色建立主次关系。
- 语义色独立表达成功、警告、错误和信息，不为了“统一”而全部染成主题色，也不让主题色与某个高风险状态难以区分。
- 保持中性色温度一致。暖画布、冷灰表面、偏绿文字和偏紫阴影等混杂关系会让界面显脏，应先统一底层色温。
- 避免单一色相统治所有层级，也避免多个相近但不一致的强调色。页面需要的是层级和节奏，不是同一颜色的深浅展示。
- 一般情况下彩色表面越大，色度越克制；单色沉浸场景可以保留较高色度，但需要减少其他颜色数量，并以内容和对比控制注意力。
- 不建立绿色、紫色或其他具体色相的静态禁用名单；对所有颜色统一检查感知亮度、色度、占用面积、对比和相邻关系。
- 阴影优先使用与环境光和中性色一致的低色度颜色，不直接用高饱和主题色制造光晕。

## 语义颜色角色

每个项目至少定义以下角色，变量名可以遵循项目惯例：

- **背景**：画布、主要表面、次级表面、悬浮表面和遮罩。
- **文字**：主要文字、辅助文字、弱化文字、禁用文字和反色文字。
- **主题**：主题色、悬停色、按下色、弱主题背景和主题色上的文字。
- **交互**：焦点、选中、悬停和按下反馈。
- **语义**：成功、警告、错误和信息，以及各自的弱背景与前景色。

不要在业务组件中直接使用“蓝色”“灰色”之类视觉名称。使用 `text-primary`、`text-secondary`、`theme`、`danger` 等语义角色，使主题可以根据项目改变。

## 文字颜色层级

- 主要文字承担标题、正文和关键数据，必须拥有最高且稳定的可读对比度。
- 辅助文字用于说明、时间和次要信息，与主要文字形成明确但不过度衰减的层级。
- 弱化文字只用于非关键占位、补充元数据和禁用信息，不承载完成任务所需内容。
- 主题色文字仅用于链接、选中状态和需要强调的短内容，不用主题色替代大段正文。
- 同一段信息只使用一个主要颜色层级，不把一句话切成许多不必要的颜色片段。

## 主题色与状态

- 主题色需要同时适配主要操作、链接、焦点和选中状态，并提供清楚的悬停与按下变化。
- 通过明度、饱和度或色度建立状态差异，不随机更换色相。
- 语义色的含义必须稳定；不要让主题色与错误、警告或成功色难以区分。
- 限制高饱和颜色的同时出现数量和面积，防止主要操作与状态提示争夺注意力。
- 深色模式需要独立调整明度、色度和表面关系，不能机械反转浅色模式。

## 配色原则参考

以下原则可在配色遇到困难时参考：

- **品牌色决定气质，中性色决定可读性，强调色只占 5% 面积**。不要平均分配三种颜色的视觉重量。
- **同一色相调明度比更换色相更安全**。页面颜色难看往往不是因为色相选错，而是每种颜色的明度太接近。拉开 HSL L 值差（至少 10–15%）比调整色相更有效。
- **暖冷搭配控制面积比**：80% 中性色 + 15% 品牌主色 + 5% 强调色。浅色背景（`L > 85%`）上不使用浅黄、浅粉、浅绿作为强调色——对比度不够。
- **焦点环颜色不透明度 ≥ 0.25**，使用品牌色而非强调色的半透明版本，确保在白色和浅色背景上都有辨识度。
- **白色背景上的阴影使用低色度黑色**（`rgba(0,0,0,0.06–0.12)`），不使用有色阴影。有色阴影仅在深色背景上有意义。

## 验证与诊断

- 普通文字与背景的对比度至少达到 `4.5:1`；大号文字和重要非文字图形至少达到 `3:1`。
- 分别检查主题色上的文字、辅助文字、禁用状态、焦点环和所有语义色组合。
- 模拟常见色觉差异，确保状态不只依赖颜色表达。
- 在真实内容、图片、图表和不同屏幕亮度下检查颜色，不只查看变量色板。
- 在完整桌面与移动截图中检查颜色面积；如果第一眼只感知到一片同色背景，再判断它是否是有意的单色沉浸场景。不是则降低用量；是则确认核心内容和操作仍然清楚。
- 缩小截图或短暂虚焦后检查页面；背景可以先形成氛围，但核心内容、产品对象或主要操作必须随即成为清晰焦点，不能被大块颜色吞没。
- 临时转为灰度检查信息层级；灰度下层级消失时，说明设计过度依赖色相而不是明度与排版。
- 检查主要操作、链接、选中、成功、警告和错误能否快速区分；不能只看它们是否分别“好看”。
- 如果配色显得冲突，按顺序诊断：统一中性色温度，减少无功能色相，降低大面积表面的色度，拉开关键明度，最后才调整主题色。
- 如果配色显得沉闷，先增加主题色与中性背景的对比或改善使用面积，不先加入更多强调色。
- 如果配色显得廉价，优先检查高饱和颜色面积、彩色阴影、多个浅色背景和语义色滥用，不用降低所有颜色对比来假装克制。

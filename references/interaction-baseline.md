# 交互基线

当任务涉及控件行为、状态切换、手势、反馈或动效时读取本文件。

## 状态设计

- 为可交互元素处理默认、悬停、聚焦、按下、禁用和处理中状态。
- 为数据界面处理首次加载、局部刷新、空数据、错误、部分成功和完成状态。
- 保持状态变化前后的尺寸尽量稳定，避免按钮文字、计数器或加载提示推动周围布局。
- 默认、悬停、聚焦、按下、选中和处理中状态必须保留相同的内容内边距、边框占位、圆角范围和对齐基线；只允许改变不会重排内容的视觉属性。
- 将错误放在用户能够修正的位置，并说明问题与下一步。
- 对耗时操作显示进度或明确的进行中状态，并防止重复提交。

## 悬停反馈与鼠标指针

- 为按钮、链接、菜单项、图标操作、可点击列表项和其他可交互元素提供清晰但克制的悬停反馈。
- 使用背景、文字颜色、图标颜色、阴影、透明度或轻微位移表达悬停，不通过改变尺寸、边距或边框宽度造成布局跳动。
- 悬停或选中背景需要保留与容器边缘和相邻内容一致的安全距离；不能让状态色突然延伸到容器外沿，使首尾图标、编号或文字看起来被裁切。
- 将 `transition` 写在元素的基础状态，使鼠标进入和离开时都能平滑过渡。
- 只声明实际变化的属性，例如 `color`、`background-color`、`box-shadow`、`opacity` 和 `transform`；不要使用 `transition: all`。
- 普通悬停反馈优先控制在 `120–200ms`，使用自然且响应及时的缓动；高频控件应更短、更克制。
- 区分装饰性 hover 和功能性 hover：**装饰性 hover**（背景/文字/阴影变化）直接写 `:hover` 并带 `transition`，不包裹媒体查询，确保在 iframe 预览、触屏笔记本等环境仍生效；**功能性 hover**（悬停展开菜单、显示操作按钮等）才用 `@media (hover: hover) and (pointer: fine)` 包裹，避免触控设备产生粘滞悬停状态。
- 不用悬停替代聚焦、选中或按下状态；键盘和触控用户必须获得等价反馈。
- 按交互语义设置 `cursor`，不要让所有元素都保持 `default`，也不要给所有元素统一设置 `pointer`。
- 为按钮、链接和明确可点击的区域使用 `pointer`；优先使用原生 `button` 和 `a`，不要仅靠鼠标指针伪装普通容器。
- 为文本输入和可选择文本保留 `text`，为拖拽对象使用 `grab` 与拖拽中的 `grabbing`。
- 为不可用操作使用 `not-allowed`，为正在处理且暂时阻塞的操作使用 `progress` 或适合平台的忙碌指针。
- 为调整尺寸、缩放、移动和精确选择使用对应的系统指针，不自造难以理解的鼠标样式。
- 次级按钮不能与所在表面融为一体；当填充色与背景过近时，使用持续占位的描边、对比明确的中性填充或文字按钮形态，并在默认与交互状态都保持可辨认边界。

```css
.action {
  cursor: pointer;
  transition:
    color 160ms ease,
    background-color 160ms ease,
    box-shadow 160ms ease,
    transform 160ms ease;
}

@media (hover: hover) and (pointer: fine) {
  .action:hover {
    background-color: var(--action-hover-bg);
    box-shadow: var(--shadow-hover);
    transform: translateY(-1px);
  }
}

.action:disabled {
  cursor: not-allowed;
}
```

## 动效判断

- 进入、退出和移动保持方向与触发来源一致。
- 允许可能被快速重复触发的过渡被中断和重新定向。

## 动效实现

- 优先动画不会持续触发布局计算的属性，如 `transform` 和 `opacity`。
- 避免使用大幅缩放、长距离位移和无目的循环运动吸引注意。
- 为展开、折叠和尺寸变化预留稳定布局，避免内容闪烁或跳动。
- 保持同一产品内的时序、方向和缓动逻辑一致。
- 在较慢播放速度下检查起点、终点、遮挡、重叠和中断行为。

## 浮层与菜单动效

- Dialog、Drawer、Popover、Dropdown、Tooltip 和菜单都需要明确的进入与退出过渡，不能在无反馈的情况下瞬间出现或消失。
- 不能只在设计说明中写“需要过渡”；实现时必须存在可检查的打开态、关闭态、过渡属性和关闭完成后的清理逻辑。
- Dialog 背景遮罩优先使用 `opacity` 淡入淡出，面板使用小幅 `opacity + transform`；位移通常控制在 `6–16px`，缩放保持在 `0.98–1`，避免夸张弹跳。
- Popover 和 Dropdown 从触发器锚点方向进入，优先使用 `4–8px` 位移与透明度变化；退出方向与进入相反，并略快于进入。
- Tooltip 使用更短的淡入淡出，避免长距离移动；连续浏览相邻目标时不要反复播放显眼动画。
- 普通浮层进入优先控制在 `160–240ms`，退出控制在 `120–200ms`；高频菜单和 Tooltip 可以更短。
- 在元素基础状态声明明确属性的 `transition`，不使用 `transition: all`。优先动画 `opacity` 和 `transform`，避免动画布局尺寸。
- 关闭浮层时先进入退出状态，动画完成后再移除节点或设置不可见；退出期间阻止重复操作，且不能留下可聚焦的隐藏内容。
- 分别验证点击触发器、点击外部、选择选项、按 `Escape`、提交表单和程序化关闭这些路径；每条路径都必须经过同一退出过渡与焦点返回逻辑。
- 尊重 `prefers-reduced-motion`，将位移和缩放降为近乎即时的淡入淡出，但保留状态可见性。

## 输入方式

- 为键盘操作提供合理顺序、清晰焦点和可执行的确认与退出方式。
- 为触控和键盘提供与悬停等价的状态反馈。

## 减少动态效果

- 尊重 `prefers-reduced-motion`，减少位移、缩放、视差和持续运动。
- 保留对理解状态有帮助的颜色、透明度或即时反馈。
- 确保关闭运动后不会丢失内容、操作结果或流程提示。
- 不让动效成为读取信息或完成任务的必要条件。

## 覆盖层与焦点

- 打开对话框、抽屉和菜单时，将焦点移动到合理位置。
- 在模态界面中限制焦点范围，关闭后将焦点返回触发位置。
- 支持明确的关闭操作和适用场景下的 `Escape` 键。
- 避免多个覆盖层无规则叠加；明确层级、背景交互和滚动策略。
- Popover 和 Dropdown 应锚定触发器并在视口边缘自动翻转或调整位置，箭头、菜单边缘和触发器保持稳定间距。
- 点击外部是否关闭必须与任务风险一致；存在未保存输入时不要静默丢失内容。

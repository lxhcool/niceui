# 验证清单

在完成界面实现或审查前读取本文件。只执行与当前任务相关的项目，但不要跳过核心工作流。

## 快速门禁（平台通用）

在完整执行验证清单前，先确认以下跨平台机械门禁全部通过。任意一项未通过则不进入后续审查：

1. 全应用任何文字的渲染字号 ≤ 22px（无例外）
2. 界面无 Lorem ipsum、"设计说明"、"示例"、"占位符" 等非产品文案
3. 已定义全部语义颜色令牌（Web 的 :root 变量 / React 的 ThemeConfig / Flutter 的 ThemeData）
4. 滚动区域使用自定义外观（Web 的 ::-webkit-scrollbar / Flutter 的 ScrollbarTheme）
5. 悬停效果有限制（Web 的 @media query / Flutter 的 MouseRegion 条件处理）
6. 有动效降级处理（Web 的 prefers-reduced-motion / Flutter 的 reduceMotion 检测）
7. 至少一个窄屏响应式处理（Web 的 @media / Flutter 的 LayoutBuilder）
8. 容器组件具有明确圆角声明（包括 0，不允许无定义）
9. 表单控件已自定义（无原生 select / checkbox / date 暴露）
10. 新建页面已与项目已有页面执行风格距离检查
11. 新建或重塑页面首屏通过 1 秒识别检查，隐藏品牌名后仍能看出产品类型、主对象和主要动作

这些项目是 NiceUI 的最低质量门槛。不满足则不进入视觉审查。

## 质量标准评分（参考 design-methodology.md）

完成视觉审查后，可按以下维度评分（100 分制）：

| 维度 | 分值 | 检查要点 |
|---|---|---|
| 信息层级 | 20 | 一眼能看出页面目标和主要动作；标题/正文/辅助文字层级分明 |
| 排版质量 | 20 | 字号序列完整、行高舒适、对齐一致、无随机字重 |
| 间距一致性 | 15 | 所有间距来自固定序列、区块节奏清晰、无随机值 |
| 视觉重点 | 15 | 每页一个主视觉或主操作、按钮层级明确、无多个同等竞争元素 |
| 组件一致性 | 10 | 圆角/阴影/按钮/卡片来自同一套规范、不混用多种风格 |
| 图片与素材 | 10 | 素材风格统一、质量达标、不混用不同视觉形式 |
| 移动端体验 | 10 | 非简单缩小、触控友好、信息重新排级 |

质量评分 ≥ 80 分为合格，< 80 分需说明改进方向。

平台特定的详细检查项见对应的 `impl-*.md` 文件。

## 功能

- 主要任务可以从入口完整执行到结果。
- 所有可见控件都能操作，并产生与文案一致的结果。
- 加载、空数据、错误、禁用、成功和重复操作按预期工作。
- 导航、返回、取消、关闭和刷新不会造成意外状态丢失。
- 外部资源失败或数据异常时，界面仍提供可理解的反馈。

## 视觉

- 页面具有清晰的第一注意目标和稳定的信息层级。
- 首屏 1 秒内能看出产品类型、主对象和主要动作；如果只能看出标题、说明、按钮、抽象背景或通用卡片，判定失败。
- 页面骨架符合内容类型；聚焦单列、主次双列、侧栏、数据网格或画廊不是无理由套用。
- 页面已通过“类型内模式检查”：官网、博客或其他载体选择了由真实内容关系支持的构图模式，没有因为页面名称自动套用唯一骨架。
- 视觉方向来自当前产品、用户和内容，不是可随意替换名称的通用模板。
- 页面已通过换名、缩略图、灰度、去文案和相邻项目检查；隐藏 Logo 后仍能从真实对象、内容类型或空间关系辨认产品。
- 新建或重塑页面在编码前比较过三个实质不同的灰度结构剪影，没有把换色或换圆角当成不同方案。
- 三个结构剪影至少有一个在阅读方向、列数、主对象或区段组织上区别于该类型最常见的默认做法；选择结果有任务依据。
- 同页没有无依据地组合胶囊标签、双 CTA、右侧 Mockup、三卡片、四步骤和深色 CTA；出现三项以上时已重新设计或记录内容依据。
- 页面最多有一个主要辨识点，且该辨识点不会压过核心任务。
- 对齐、间距、字号、图标和控件尺寸遵循一致节奏。
- 页面边距、区段间距、组件间距与控件内边距形成可辨认的关系层级，没有散落的任意距离。
- 需要居中的内容在水平和垂直方向准确稳定；需要扫描的正文、表单和数据没有被错误居中。
- 图标与文字、不同字号文字、同一行控件分别完成视觉中心、基线和高度对齐检查。
- 表格、网格和重复列表沿统一列线对齐，状态变化不会破坏中心线或列线。
- 已逐项对比默认、悬停、聚焦、按下和选中状态；内容内边距、边框占位、圆角范围、行高与列线保持不变，状态背景没有贴边或裁切首尾内容。
- 全页面所有文字的实际计算字号均不超过 `22px`；标题、文章标题、数据、按钮、标签和宣传文案都必须包含在检查范围内。
- 字体角色完整且一致，页面标题、区段标题、正文、辅助文字、标签和数据没有散落的任意字号。
- 文本、数字、图片和动态内容没有溢出、遮挡或意外换行；单行动态文案在空间不足时显示省略号，必须完整阅读的正文和错误信息能够合理换行。
- 所有包含“弹性文字 + 固定操作/价格/状态/图标”的 Flex 或 Grid 行都完成抗挤压检查：文字容器可收缩且具有 `min-width: 0` 或零最小轨道，固定内容不收缩、不变形、不被推出容器。
- 悬停、焦点、按下、选中和禁用状态容易区分。
- 与所在表面颜色接近的按钮已改用可见描边、对比填充或清楚的文字按钮形态；默认状态下也能辨认为操作，不能只依赖悬停才显现。
- 所有列表滚动区域都使用协调的自定义轨道与滑块视觉，没有直接暴露系统原生滚动条，同时保留滚轮、触控、键盘与辅助技术能力；大数据列表按性能需要使用真正的列表虚拟化。
- 页面没有直接展示浏览器原生 `select`、复选框、单选框或日期选择器；自定义控件具有完整语义、键盘操作、校验与重置行为。
- 所有下拉触发器的图标库箭头与右边缘保持稳定间距，长文案不会覆盖箭头。
- 已记录选用的图标库；功能图标全部来自该库，没有临时手绘 SVG、Emoji 或不同体系混用。
- 可交互元素具有符合语义的鼠标指针，没有全部停留在 `default`，也没有无差别使用 `pointer`。
- 悬停反馈带有进入和离开都生效的平滑过渡，没有使用 `transition: all` 或会引发布局跳动的属性。
- 纯悬停效果只在支持悬停的精确指针设备上启用，触控和键盘仍能获得等价反馈。
- 内容主要通过留白、背景、对齐和排版分组，没有依赖卡片边框或贯穿式分割线。
- 页面区段、卡片、导航分栏和普通列表项从零结构边框开始；每一条保留的结构边界都对应明确的输入、数据扫描、拖放或层级语义。
- 已执行移除边框测试；隐藏结构性描边后层级仍然成立，没有同时依赖外层面板框、内部行分割线和控件描边。
- 按钮圆角与控件高度、密度和产品气质协调，柔和但不膨胀；整页圆角保持少量层级，没有无意义的胶囊化。
- 页面颜色彼此协调，强调色和语义色没有冲突或同时争夺注意力。
- 配色由当前产品语境推导，主要文字、辅助文字、主题色、背景和语义状态使用稳定的语义变量，没有写死为 NiceUI 通用色板。
- 中性色温度一致，画布与表面主要依靠明度建立层级，没有冷暖灰、彩色阴影或多个浅色背景互相污染。
- 主题色面积受到控制，没有把同一色相铺满背景、表面、导航、文字和控件；页面在灰度下仍有清晰层级。
- 页面没有无意图的大块亮色或高色度背景；缩略观察时，颜色形成的氛围、内容层级和主要操作拥有清楚的先后关系。
- 如果页面使用整片强色、渐变或深色场景，该颜色集中形成一个连续主视觉，其他区域没有继续堆叠竞争色，文字与交互仍保持稳定对比。
- 主要操作、链接、选中、成功、警告和错误在真实组合中容易区分，主题色不会与危险状态混淆。
- 阴影只用于必要层级，边缘柔和，没有浓黑脏边、彩色光晕或全页面漂浮感。
- 留白能够表达内容关系，但没有造成区段松散、首屏空洞或操作距离过长。
- 没有无理由的装饰、重复容器或相互竞争的强调元素。
- 同一页面没有连续复用相同卡片网格；至少一个主要区段由真实内容、排版、图像、数据或操作过程组织。
- 首屏展示真实或接近真实的产品对象，没有用抽象横线、假图表和无业务含义的 Dashboard 骨架代替核心内容。
- 新建页面已建立页面对象清单，首屏至少出现 `2` 类真实材料，整页至少出现 `4` 类真实材料；材料的形式由当前产品决定，不要求固定布局。
- 唯一创意点来自产品内容、操作或品牌语境；移除后不影响可用性，保留时能增加理解或记忆。
- 参考案例已经过 NiceUI 规则过滤，没有整套照搬不匹配的风格、配色或页面结构。
- 示例中的色值、圆角、间距和版式没有被当成跨项目固定模板，关键取值都能由当前内容、尺寸或既有设计系统解释。
- 多张参考图已经区分稳定偏好、局部做法和冲突候选；最终结果学习了关系与细节，没有复刻某一张图的完整轮廓。
- 已与同一项目近期页面并排执行风格距离检查；没有把相同字体组合、底色、眉题、居中限宽、圆角、图片处理和轻微悬停成套复用。
- 当任务要求多个不同风格页面时，相邻页面至少在四个风格维度形成可观察差异，且不能只靠骨架和换色通过；每个差异都有产品或参考依据。
- 如果主动查找了参考，已说明每个来源解决的问题、采用的关系和不采用的显眼特征；没有把平台网站本身当作风格标签。

## 响应式

- 至少检查一个窄屏、一个常规桌面和一个宽屏尺寸。
- 检查断点附近尺寸，确认布局不会在区间中间失效。
- 使用最长可信名称、路径、金额、状态和按钮文案做窄宽压力测试，分别让左右两侧内容接近上限，确认不会互相挤压变形。
- 导航、工具栏、表格、弹窗和固定元素不会遮挡主要内容。
- 横向滚动仅出现在明确允许的区域。
- 触控目标、软键盘和安全区域不会阻碍核心操作。

## 可访问性

- 使用正确的语义元素，控件具有可访问名称。
- 键盘可以到达并操作所有关键功能，焦点清晰可见。
- 标题结构、表单标签、错误关联和状态通知合理。
- 文本与重要图形具有足够对比度，信息不只依赖颜色。
- 减少动态效果设置生效，且不会破坏功能。

## 动效与性能

- 动效具有明确目的，不拖慢高频操作。
- 动态参考已被拆成进入、触发、推进、衔接、反馈、退出和降级规格；实现没有只复制表面运动。
- Dialog、Popover、Dropdown 和 Tooltip 都存在可检查的打开态、关闭态与真实过渡；触发器、外部点击、选择、`Escape`、提交和程序化关闭路径均已验证，退出后不会残留焦点或可点击内容。
- 动效起点、方向、时序和结束状态符合交互关系。
- 快速重复操作不会导致跳变、堆积或错误状态。
- 页面加载时没有明显布局跳动，图片和固定比例区域拥有稳定尺寸。
- 检查浏览器控制台、失败请求和明显的渲染性能问题。

## 工程质量

- 复用现有组件、设计变量和工具，不引入重复实现。
- 没有无关重构、临时代码、失效样式或调试输出。
- 运行项目适用的类型检查、测试、代码检查和构建命令。
- 查看最终差异，确认改动范围与任务一致。
- 记录无法执行的验证及其原因，不把未检查结果描述为已通过。

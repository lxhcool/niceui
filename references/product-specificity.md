# 产品辨识与非模板化

在新建页面、明显重塑页面、使用视觉参考，或用户认为结果具有模板感、AI 感时读取本文件。目标不是刻意追求怪异，而是让页面结构、内容与视觉表达能够从当前产品的证据中推导出来。

## 建立产品指纹

编码前从项目、用户描述、现有内容和视觉资产中提取：

- `3` 个产品特有的对象，例如画布、订单、作品、航线、病历或代码变更。
- `3` 个用户高频动作，例如比较、筛选、编辑、审批、收藏或发布。
- `3` 类可以真实展示的材料，例如数据、图片、界面状态、人物、文档或操作记录。
- `3–5` 个具体性格词，描述产品应显得精密、亲切、直接、活跃、沉静或其他特征。
- 一个即使隐藏 Logo 仍能帮助识别产品的信号。

不要从产品名称联想装饰风格。没有证据支持的渐变、网格、光晕、玻璃、3D、噪点和插画不能成为产品指纹。

如果当前信息不足，优先从代码、真实文案、数据结构和已有资产继续推断。只有关键选择会显著改变结果且无法推断时再询问用户。

## 参考驱动的结构抽取

当用户给出“类似某产品、某网站、某应用、某页面或某截图”时，先把参考拆成可迁移关系，再设计当前产品。参考抽取必须先于配色、字体和组件细节，且不得变成固定风格模板。

内部记录以下字段：

- `参考类型`：参考本身是内容平台、商店、工具、社区、官网、后台、作品集还是其他产品载体。
- `首屏抓点`：第一眼看到的真实对象是什么，例如商品图、游戏封面、数据表、地图、文档、视频、头像、代码或订单状态。
- `对象清单`：参考中反复出现并定义产品类型的对象，例如封面、评分、价格、库存、榜单、评论、时间线、筛选器、编辑区或预览。
- `动作入口`：用户可立即执行的动作，例如搜索、筛选、比较、下载、预约、购买、编辑、审批、收藏、评论或分享。
- `信息密度`：参考偏展示、常规、紧凑还是高频扫描；当前页面必须选择相容密度，不能因为美观而稀释核心对象。
- `可迁移关系`：可以迁移到当前产品的空间关系、内容顺序、状态表达和交互方式。
- `拒绝复刻项`：至少列出两个不采用的表层特征，例如固定色值、特定圆角、整页比例、装饰图形、品牌符号或文案语气。

如果用户的参考与当前页面职责冲突，先保留参考的用户预期和内容关系，再根据当前产品修正页面类型。例如“类似某商店”的重点通常是发现、比较、判断和交易，而不是照搬该商店的颜色或卡片尺寸。

参考中最能定义产品类型的结构信号，必须在当前页面中保留足够数量。数量不固定，但必须能回答：隐藏 Logo 和标题后，用户是否仍能通过对象、状态和动作看出“它像那个类型的产品”。不能只保留暗色、渐变、玻璃、圆角、留白或按钮样式。

## 判定产品载体与页面职责

先做两层判断，不能只得出“这是一个网页”。

第一层判断产品载体。载体决定用户预期、内容证据和整体节奏：

| 产品载体 | 用户预期 | 默认设计重心 | 避免自动套用 |
| --- | --- | --- | --- |
| 博客、杂志、内容站 | 找文章、连续阅读、形成作者或刊物认知 | 标题层级、发布日期、作者、阅读宽度、相关文章与归档 | 功能卡片、产品 Mockup、密集 CTA |
| 品牌或产品官网 | 快速理解是谁、提供什么、是否可信并采取行动 | 清楚主张、真实产品或案例、客户证据、价格或联系路径 | 三卡片功能区、四步骤、空泛口号 |
| 后台、管理系统 | 高频查询、维护、审批和监控 | 稳定导航、信息密度、批量操作、状态、权限和异常 | 巨型 Hero、营销文案、大面积装饰 |
| 商店、交易平台 | 发现、比较、判断并购买 | 商品内容、价格库存、规格、评价、配送与结算 | 用品牌氛围遮盖交易信息 |
| 作品集、画廊 | 浏览作品并理解创作者能力 | 作品本身、媒介差异、项目语境和联系路径 | 等宽缩略图填满全站、虚构指标 |
| 文档、知识库 | 定位答案并持续阅读 | 信息架构、搜索、目录、版本、代码或示例 | 营销式首屏和频繁视觉打断 |
| 社区、社交产品 | 发现人与内容并参与 | 身份、时间、关系、反馈状态和内容流 | 将真实内容压缩成抽象卡片 |
| 独立工具、编辑器 | 直接完成一个任务 | 工作对象、输入输出、历史、快捷操作与恢复 | 先讲产品再让用户使用 |

第二层判断当前页面职责。职责决定这一页的主轴：

- 首页负责建立方向和入口，不承担所有细节。
- 列表页负责检索、比较、筛选和批量动作。
- 详情页负责围绕一个对象建立完整判断。
- 编辑页负责输入、预览、校验、保存和恢复。
- 仪表盘负责暴露变化、异常与下一步，而不是陈列所有指标。
- 设置页负责解释影响范围、依赖关系和危险操作。
- 登录、结算、发布等流程页负责减少分心并完成单一任务。

同一载体的不同职责也不能共用同一骨架。例如博客首页可以强调选题与最新内容，文章详情必须优先阅读；后台仪表盘强调变化，后台列表页强调扫描与操作。

完成判断后，在内部写出一句路由结论：

`这是一个 [产品载体] 的 [页面职责]，主要用户要 [核心动作]，因此页面优先 [内容与空间关系]。`

如果这句话仍可无损替换成完全不同的产品，继续读取真实内容和代码。一个页面可以混合类型，但首屏只能有一种主要阅读路径。

**载体判断会直接影响配色方向**：确定产品载体后，若页面没有品牌资产可提取主色，参考 [视觉系统](visual-system.md) 的「按产品类型定色相」表格锁定色相家族。后台、工具类载体的主色饱和度控制在 30-50%，面积 ≤ 5%。例如：金融后台用深蓝、医疗后台用墨绿、开发者工具用炭黑 + 强调色——类型先决定色相，再谈具体色值。

## 建立页面对象清单

在新建页面、重塑页面或用户指出“模板感/不好看/不像参考”时，必须先建立当前页面的对象清单。对象清单不是固定模板，而是防止模型只生成标题、说明和卡片。

按页面职责选择至少 `4` 类真实材料进入页面，且首屏至少出现其中 `2` 类：

| 页面职责 | 可选真实材料 |
| --- | --- |
| 官网首页 | 产品截图、实际服务对象、案例结果、价格/套餐、客户证据、使用流程中的真实状态、联系或试用入口 |
| 内容/博客首页 | 文章标题、发布日期、作者、专题、封面图、阅读时长、标签、精选理由、归档入口 |
| 商店/交易页 | 商品图、价格、规格、库存、评价、配送、筛选状态、购物车状态、对比或推荐理由 |
| 社区/平台首页 | 内容流、作者/用户、时间、评论/点赞、分类、榜单、搜索、关注/发布入口、热度状态 |
| 游戏/媒体页面 | 封面或截图、评分、预约/下载、版本状态、平台、分类标签、玩家评价、社区热度、更新日志、视频入口 |
| 后台/仪表盘 | 业务对象、关键状态、异常、时间范围、趋势、列表、负责人、批量动作、导出或处理入口 |
| 工具/编辑器 | 输入对象、输出结果、画布/预览、工具栏、历史记录、校验状态、保存/撤销/运行入口 |
| 文档/知识库 | 搜索、目录、版本、文档标题、代码/示例、更新时间、路径、相关内容 |

这些材料的具体表现形式由当前产品决定：可以是图片、数据、列表、表格、地图、时间线、媒体、Canvas、表单或操作记录。不得把表中的材料写成固定布局，也不得机械凑满所有项。

执行“对象优先”排序：先让真实对象占据首屏主要视觉或操作面积，再安排标题和说明。除品牌活动、艺术展示等少数场景外，标题不能成为唯一的大对象。

## 选择类型内的构图模式

产品载体和页面职责确定后，再从构图模式中选择。以下是候选关系，不是模板清单；必须用当前内容解释为什么选择它。

### 官网、品牌和产品页

- **沉浸封面**：当产品有真实的 3D、Canvas、视频、动态视觉或环境素材时，让它组成一个连续的首屏场景；文字和行动入口附着在场景关系上，不额外堆叠说明区。
- **产品对象优先**：当用户需要理解产品如何工作时，让真实界面、操作过程或结果成为第一对象，主张、价格或入口围绕它排列。
- **案例序列**：当可信度来自作品、客户、地点或结果时，先展示真实案例序列，再安排产品介绍和行动入口。
- **编辑式官网**：当品牌内容复杂、需要持续阅读时，使用窄阅读轴、索引、故事段落与少量媒体，而不是营销卡片网格。

沉浸封面只在动态内容本身有品牌或产品意义时使用。没有真实素材时，不能用抽象渐变、假 Canvas 或循环动画填补首屏。

### 博客、杂志和内容站

- **编辑双栏**：主列连续文章，侧列放本期索引、作者、专题或归档；适合有明确刊物结构的首页。
- **三栏选题**：当文章有封面、作者、分类或状态等可比较元数据时使用三栏；图片承担主要色彩，文字保持紧凑。
- **组件化阅读流**：当内容是短笔记、链接、代码片段、引用或产品记录时，用不同长度的内容组件组成流，不强行统一成文章卡片。
- **社交流**：当核心关系是作者、时间、回复、转发和收藏时，优先使用时间线或内容流；头像、状态和关系信息必须是真实内容，不用装饰性人物卡。
- **专题档案**：当读者需要按主题、年份或作者浏览时，使用索引、筛选、密集列表或横向目录，把文章检索放在首屏。

博客首页只能选择一个主要阅读方向。双栏和三栏不是为了填满页面，必须由文章元数据和阅读动作支撑；没有图片或比较关系时，保持编辑式单列更合理。

### 其他内容与展示页面

- 作品集可以采用项目序列、单一案例叙事、横向画廊或作者档案，取决于用户是浏览作品还是理解一个项目。
- 社区可以采用时间流、主题分栏、问答列表或个人档案，取决于关系、时间和参与动作。
- 文档可以采用目录 + 阅读轴、搜索 + 结果、版本对照或示例工作区，不能自动套博客或官网的 Hero。
- 商店可以采用商品画廊、比较表、编辑选品或单品叙事，取决于发现、比较和购买哪个动作最重要。

形成内部结论：`当前类型使用 [构图模式]，因为它让 [真实内容关系] 更容易完成 [用户动作]。` 如果只能说“看起来更丰富”，淘汰该模式。

对后台、工具和编辑器额外执行首屏门禁：

- 首屏主要面积必须是工作对象、输入、结果、数据或操作历史，而不是标题和产品介绍。
- 页面标题用于定位当前位置，保持常规应用层级；不使用跨多行超大标题制造视觉中心。
- 不设置“我们如何工作”“为什么选择我们”“从产品出发”等方法宣言。
- 用户进入后应能在一个视口内开始主要任务；需要先阅读长段落才能操作时，判定类型路由失败。

## 生成结构剪影

新建或明显重塑页面时，在进入视觉样式和编码前形成 `3` 个灰度结构剪影。可以是草图、简短布局描述或低保真 HTML，但必须满足：

- 不使用颜色、阴影、渐变和装饰字体区分方案。
- 三个方案在阅读方向、主对象位置、信息密度和区段组织上具有实质差异。
- 分别说明桌面主轴与移动端如何重组、隐藏或改序。
- 每个方案只保留一个主要辨识点。
- 根据任务效率、内容关系、产品指纹和实现稳定性选择一个方向。
- 三个剪影都必须标注首屏出现的真实对象、主要动作和参考结构信号；没有对象差异的剪影不算有效方案。

只有配色、圆角或图片不同的方案视为同一个剪影。不能通过制作三个近似版本假装完成比较。

不必默认向用户展示所有剪影；当比较能够帮助用户做真实决策时再展示。

## 过滤通用落地页

以下模式容易组合成通用 AI 落地页：

- 胶囊标签、居中大标题、说明文字和两个 CTA。
- 左侧文案、右侧圆角产品 Mockup。
- 三张等宽功能卡。
- 四步工作流程。
- 深色横幅 CTA 和极简页脚。
- 每个区段都使用同样的圆角卡片。
- 使用抽象横线、假图表和无业务含义的 Dashboard 骨架。
- 依赖“不是……而是……”“从 A 到 B”“简单、清晰、高效”等通用句式。
- 使用 `01 / 02 / 03` 只是为了让并列内容显得完整。

这些模式不是静态禁用项，但同一页面出现 `3` 项以上时，必须逐项说明它们为何来自当前内容和任务。无法说明时，重新选择结构或删除模式。

不要通过随机旋转、错位、不同圆角和更多颜色掩盖模板结构。非模板化首先来自信息关系与主对象，而不是视觉异常。

## 控制组件重复

- 同一页面最多默认保留一组等宽卡片阵列；更多阵列必须由真实重复数据支持。
- 连续两个区段不要使用相同列数、相同卡片尺寸和相同标题结构。
- 至少一个主要区段通过排版、真实内容、图像、数据或操作流程组织，而不是通过卡片组织。
- 不为三个句子分别创建三个容器，也不为一个流程机械创建四个步骤。
- 卡片、表格、列表和画廊只在内容具有对应关系时使用。
- 组件可以复用，但页面节奏不能只靠重复同一组件产生。

## 使用真实内容

- 首屏优先展示一个可辨认的真实对象：产品界面、人物、作品、数据、文档、商品或操作结果。
- 首屏至少有一个对象承担主要视觉重量或操作重量，例如可识别媒体、商品、列表、表格、地图、编辑画布、业务状态或内容流；抽象背景、装饰插画、渐变色块和通用 Mockup 不能单独承担这个角色。
- 产品演示使用真实字段、状态和行为，不用抽象矩形代替核心内容。
- 文案说明具体对象、动作和结果，不只描述“体验更好”或“提高效率”。
- 功能介绍优先通过真实前后状态、任务路径或内容样本表达。
- 如果内容本身色彩丰富，让内容承担主要颜色，导航与画布降低色度。
- 如果使用强色背景，让它形成一个完整连续场景，其他区段恢复安静。
- 页面内只写最终用户需要的内容，不写给设计者或评审者看的解释。禁止将“设计说明”“结构批注”“色彩策略”“这个区域用于……”“示例数据”“Demo”等元叙事做成页面内容，除非产品本身就是设计教学或审查工具。
- 不为了展示组件而制造无任务关系的按钮、卡片、图表或状态。出现的控件必须能执行、导航、展开、筛选、提交，或明确处于禁用状态。
- 真实内容暂时不可得时，使用长度、状态、数量和语义接近生产环境的拟真内容；在交付回复中说明替换需求，不在页面中标注“占位”或“稍后替换”。
- 执行去说明测试：删除所有宣传性和解释性段落后，只看对象、字段、数据、状态与操作，仍应能判断它是什么产品、正在完成什么任务。
- 执行首屏 1 秒测试：把首屏缩小到缩略图或快速扫一眼，仍应能看到当前产品类别的对象密度和主要动作；如果只留下“漂亮背景 + 标题 + 按钮”，则判定失败。
- 执行文案角色检查：逐段标记为对象内容、字段、状态、操作结果、必要帮助或营销说明。工具与后台首屏不保留营销说明；连续两段必要帮助应优先改成更清楚的字段或结构。

## 分析视觉参考

不要给参考图只贴“极简”“科技”“高级”等风格标签。逐张提取：

- 首个注意目标与主要阅读路径。
- 页面边缘、主容器和内容组使用的对齐轴。
- 最大、次大和最小间距分别表达什么关系。
- 哪些内容使用容器，哪些内容依靠留白或裁切存在。
- 颜色集中在背景、产品内容、操作还是状态。
- 页面是否使用中心、边缘、偏置、超出视口或连续场景构图。
- 图片、数据、文字和控件谁承担主要视觉重量。
- 移动端需要保留、重排和舍弃什么。
- 唯一辨识点为什么属于该产品。

多张来自同一设计系统的截图视为一个系统样本。互相矛盾的参考保留为不同候选，不把它们平均成一种安全风格。

## 执行辨识度检查

实现前后分别执行：

### 换名测试

把产品名称替换成任意 AI、金融或效率工具名称。如果页面仍然完全成立，说明结构或内容缺少产品证据。

### 缩略图测试

将页面缩小或短暂虚焦，检查首屏轮廓、主对象和颜色面积。最近完成的不同项目不应拥有相同的首屏剪影。

缩略图必须能回答三个问题：它是什么类型的产品，主对象是什么，用户第一步能做什么。答不出来时，不通过。

### 灰度测试

移除色相后检查层级与阅读路径。结构不能依赖主题色才成立。

### 去文案测试

暂时忽略标题和宣传文案，检查真实对象、布局和内容类型是否仍能表达产品类别。

如果删除品牌名和大标题后页面仍只剩无业务含义的抽象图形、均质卡片或泛指标，说明对象清单失败。

### 模式计数

统计胶囊标签、双 CTA、右侧 Mockup、三卡片、四步骤和深色 CTA 等通用模式。同页出现 `3` 项以上且缺少内容依据时，判定为模板风险。

### 相邻项目测试

与近期完成的页面或项目并排查看灰度缩略图与彩色缩略图。导航位置、首屏骨架、卡片组合、区段节奏和 CTA 位置如果高度相似，至少重新设计其中一个主要关系。**颜色层面同样必须检查**：相邻项目不得连续复用同一色相家族与色彩模式（如连续两次暖灰画布 + 低饱和灰绿品牌 + 磨砂表面）；出现整套复用时，换色相、换色彩模式或换材质，而不是只换按钮颜色。

通过这些检查不是为了让每个页面都怪异，而是确保相似之处来自平台规范和任务共性，不同之处来自产品内容与使用语境。

## 检查风格距离

新页面与同一项目近期页面逐项比较以下维度：

| 维度 | 检查内容 |
| --- | --- |
| 骨架 | 首屏主对象、导航位置、容器宽度、阅读方向和区段组织 |
| 排版 | 字体类别、标题形态、正文比例、元数据语言和是否依赖等宽眉题 |
| 色彩 | 明暗模式、色温、主题色面积、图片是否承担色彩 |
| 形状 | 直角、微圆角、柔和圆角、胶囊和特殊轮廓的关系 |
| 边界与材质 | 留白、描边、硬分割、阴影、透明、纹理或光照 |
| 图像 | 摄影、插画、3D、界面截图、抽象图形、裁切和处理方式 |
| 控件 | 按钮层级、导航、表单、选择和状态反馈的视觉语气 |
| 时间节奏 | 进入、滚动推进、hover、press、切换与退出方式 |
| 密度 | 首屏信息量、区段距离、扫描速度和移动端取舍 |
| 记忆点 | 隐藏 Logo 后仍能辨认的产品信号 |

平台规范和同一品牌系统允许部分维度一致，但不能整套重复。对于明确要求“不同风格”的一组页面：

- 至少在 `4` 个维度形成可观察差异，其中至少 `2` 个来自排版、边界材质、图像、控件或时间节奏，不能只靠骨架和换色通过。
- 不得连续复用“暖灰或米白画布 + 小号等宽英文眉题 + `20–22px` 中粗标题 + 居中限宽 + 低饱和图片 + `6–8px` 圆角 + 轻微上浮”这一整套编辑式组合。
- 复用同一图片、配色或字体时，必须有品牌或内容连续性依据，并在其他维度拉开差异。
- 缩略图不同但近看组件、排版和动效完全相同时，仍判定风格距离不足。

不要为了通过计数随机更换颜色、旋转卡片或增加特效。每个差异都必须能由产品对象、用户动作、使用环境或参考证据解释。

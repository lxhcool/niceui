# 构图与细节

在新建页面、明显改变整体布局或需要提高完成度时读取本文件。提取关系和判断方法，不复制参考网站的固定结构。

## 先选布局骨架

- 根据核心任务选择骨架，不先选择流行版式。
- 进入视觉样式前形成三个灰度结构剪影；它们必须在阅读方向、主对象位置、密度和移动端重组上具有实质差异。
- 聚焦单列适合一个主张、一个人物、一个产品演示或连续阅读。
- 主次双列适合主要工作区与辅助信息并存；主列承担任务，次列补充上下文。
- 稳定侧栏适合高频、多模块工具；导航保持安静，内容区拥有清晰列线。
- 数据网格适合比较和监控；先确定主指标，再安排支持性图表和列表。
- 内容画廊适合图像、作品、人物或商品；统一裁切与元数据节奏，避免每张卡片自行设计。
- 可以组合骨架，但首屏只能有一个主阅读路径，不能同时要求用户横向、纵向和自由探索。
- “官网”不是布局骨架。不要自动使用左文案右 Mockup、三张功能卡和深色 CTA。
- “标题很大”不是视觉层级。标题尺寸由页面职责、阅读距离和同屏任务决定；后台、工具与编辑器默认使用常规应用标题，让工作对象承担主要面积。
- 类型路由完成后，从沉浸封面、产品对象优先、编辑双栏、三栏选题、组件化流、社交流、专题档案等候选关系中选择一个；候选必须由真实内容和用户动作支持。
- 官网可以使用大封面、Canvas、视频或背景场景，但素材必须是真实的产品、品牌或内容资产；没有真实素材时回到内容优先的结构，不用抽象动画装饰。
- 博客不默认单列。文章元数据、图片、作者关系、短内容或专题索引足以支撑时，可选择双栏、三栏、组件化阅读流或社交流；不满足时不要为了变化强行分栏。

## 建立空间关系

- 把间距分为页面边缘、区段之间、同组内容、控件内部和图标文字五个关系层级。
- 相邻层级需要有可感知差异，不能只相差一两个像素而失去语义。
- 同一关系使用稳定间距；不要为了局部“看起来差不多”产生大量孤立数值。
- 列表项、卡片和控件在默认、悬停、聚焦、按下与选中状态使用同一套内容内边距和几何尺寸；状态背景不能贴住容器边缘、裁切内容或改变原有列线。
- 聚焦页面可以使用较大负空间把注意力推向一个对象；工具页面应缩短扫描与操作距离。
- 内容宽度由阅读、比较和操作需要决定。短主张可以窄，表格和图表需要更宽，长文本保持舒适行长。
- 页边距在宽屏上可以增长，但核心内容不能无限拉散；在窄屏上保留基本呼吸和触控空间。
- 先对齐容器和列，再调整文字、图标和控件的光学位置。
- 在 Flex 和 Grid 的复合行中明确谁可以收缩：可变文字轨道使用 `minmax(0, 1fr)` 或为文字容器设置 `min-width: 0`，按钮、价格、状态、图标和必要元数据使用稳定轨道或 `flex: 0 0 auto`。
- 本来只占一行的动态名称、路径、标签和元数据在空间不足时使用省略号；正文、错误说明和完成任务所需的信息允许换行，不能用隐藏溢出来掩盖内容问题。

## 完成细节

- 检查每条边缘：页面边缘、卡片边缘、输入框文字、下拉箭头、图标按钮和图片裁切都要有稳定距离。
- 检查每条轴线：标题、正文、数值、表头、控件和图标分别完成左边线、中心线或基线对齐。
- 相同功能保持相同高度、圆角、图标尺寸和状态反馈；不同层级通过少量变量建立区别。
- 并排检查最长可信文案与最窄支持宽度，确认左侧文字撑满时不会挤压右侧操作，右侧价格或状态增长时也不会让左侧图标、编号和文字变形。
- 图片承担内容时确保主体清楚、裁切有意图、比例稳定；不要让随机图片只负责填满卡片。
- 表格和列表优先保证行扫描、列识别、批量操作和状态辨认，再添加视觉装饰。
- 图表先表达比较关系，再选择形状和颜色；标签、图例、单位、时间范围和空数据都必须完整。
- 对默认、悬停、聚焦、按下、选中、禁用、加载、空、错误和成功状态逐项检查。
- 在真实文字、长名称、动态数字、不同语言、缺失图片和异常数据下检查细节是否仍成立。

## 使用一个创意点

- 每个页面只选择一个主要创意点，其余布局和组件保持稳定。
- 创意可以来自产品对象、操作方式、数据表达、内容裁切、字体关系、导航方式或一段有意义的动效。
- 创意需要强化核心任务、品牌记忆或内容理解，不能只证明实现能力。
- 让创意拥有明确边界：一个首屏场景、一种特殊数据表达、一个悬浮导航或一段关键交互，而不是扩散到所有组件。
- 不把超大字体、渐变、玻璃、3D、噪点、插画或悬浮 Dock 本身当作创意；只有与当前产品语境结合时才成立。
- 创意移除后页面仍应可用；创意保留时页面应更属于当前产品。

## 控制重复结构

- 同一页面默认最多使用一组等宽卡片阵列；更多阵列需要真实重复数据支持。
- 连续区段不要重复相同列数、卡片比例、标题位置和内容节奏。
- 至少一个主要区段使用真实内容、排版、图像、数据或操作过程组织，而不是继续添加卡片。
- 不因为内容刚好能分成三项或四步，就机械使用三卡片或四步骤。
- 页面需要稳定的组件体系，但不需要每个区段拥有相同轮廓。

## 从参考中学习

- 分开提取布局、间距、色彩、组件、图像、字体和交互，不整页复制。
- 多张来自同一设计系统的截图只视为一个系统样本，避免因数量重复而过度加权。
- 对互相矛盾的参考保留多个方向，根据产品语境选择，不强行求共同风格。
- 记录“为什么有效”：注意力如何集中、内容如何分组、距离如何表达关系、创意如何服务主题。
- 不保存参考中的固定色值、尺寸或页面结构为 NiceUI 默认模板。
